# Assumptions — Sentinel

> What are we taking for granted? Each entry names what it relies on, what
> would falsify it, the consequence if it is wrong, and its status.

---

### A-0001 — FRED `DGS*` and Treasury CMT are the same series to published precision

**Relies on:** FRED sourcing H.15 constant-maturity series from the same
Treasury par yield curve, with no independent revision or rounding.

**Falsified when:** for any shared date and tenor, the values differ by more
than 0.01.

**Consequence:** the two pipelines overwrite each other with different numbers.
The displayed value depends on which ran last. Nothing errors. Direction:
unbiased noise, worse than a bias because it cannot be corrected for.

**Status:** ASSUMED — test specified, not yet run. **Strong supporting
evidence recorded 2026-09-28**: 920 value pairs over 184 overlapping business
days, maximum absolute difference 0.0000 across all five tenors (`F-0041`).
That was a one-off script, not the B1 contract test, so this stays ASSUMED —
what has been shown is that the two sources agreed at one moment, not that a
disagreement would ever be caught.

### A-0002 — Treasury's CSV endpoint stays unauthenticated and stable in shape

**Relies on:** `home.treasury.gov/.../daily-treasury-rates.csv` remaining
public and returning tenor columns matching `TENOR_MAP`.

**Falsified when:** the fetch returns non-CSV, or the parser raises "No
recognised tenor columns in header".

**Consequence:** the same-day pipeline fails loudly and the system falls back to
FRED's one-day lag. Degradation, not corruption. Treasury *adding* a tenor is
survivable; *renaming* one is not.

**Status:** **FIRST CONTACT MADE 2026-09-28, endpoint behaves as assumed.**
`fetch_curve_csv()` returned 185 parseable rows covering 2026-01-02 to
2026-09-25, unauthenticated, with every `TENOR_MAP` key matched — no
"No recognised tenor columns" error. One unassumed property was discovered: the
rows arrive newest-first (`F-0042`).

*Original status, retained:* ASSUMED — never fetched from this project. ORDER-01 A8 is first
contact.

### A-0003 — FRED's 502s remain single-series and transient

**Relies on:** the pattern in `F-0003` — one random series per run, recovering
next attempt.

**Falsified when:** a run loses more than three series, or one series fails
three nights running.

**Consequence:** the joined `error_message` exceeds `varchar(500)`, the
`UpdateLog` insert itself throws, and **the log row is lost entirely** —
destroying the diagnostic that produced F-0001 through F-0003. Truncation
closes it; the assumption is what made it invisible.

**Status:** ASSUMED, measured over 10 runs.

### A-0004 — All Sentinel data is rebuildable from public sources

**Relies on:** every series originating from FRED, TIC, Treasury, WGC or World
Bank, with nothing user-supplied or generated-and-persisted.

**Falsified when:** any stored data cannot be regenerated by re-running the
pipelines. **The AI analyst briefs are the open question** — if persisted, they
are generated content no public source reproduces.

**Consequence:** the go-private trigger fires and the repository goes private
the same day, costing the Planner's direct access.

**Status:** ASSUMED, not verified. Verifying it means checking whether brief
output is written to the database. This assumption decides D-0026.

### A-0005 — `composite_stress.py` tolerates the frequency of `GOLD_SPOT_USD`

**Relies on:** the divergence-multiplier logic not assuming monthly spacing.

**Falsified when:** switching to a daily source changes multiplier behaviour on
otherwise unchanged inputs.

**Consequence:** tier assignments shift for reasons unrelated to the data.

**Status:** ASSUMED. The importer's `date.replace(day=1)` suggests something
downstream expects month-start keys — which makes this more likely to be load
bearing than it looks.

### A-0006 — `127.0.0.1:5432` is a disposable local database

**Relies on:** the `.env` `DATABASE_URL` pointing at the `docker-compose`
container, evidenced by an exact match on user, password `treasury`, database
name and port. A Fly tunnel would carry Fly's generated credentials.

**Falsified when:** `SELECT count(*) FROM timeseries` against it returns a
production-scale count.

**Consequence:** a future fixture that writes or truncates does so to
production. This is the exact configuration behind both recorded losses — 2,771
rows and 4,535 rows.

**Status:** ASSUMED ON CREDENTIAL EVIDENCE — which is the same class of
reasoning that failed both times. **A hostname is not an identity.** Downgrade
to TESTED only after the row-count check, and close it permanently with the
canary in ORDER-01 A4.

**Amendment 2026-09-26 - `A-0006`.** Status moves from
*ASSUMED ON CREDENTIAL EVIDENCE* to **IDENTIFIED, UNGUARDED**. The database at

config file - PostgreSQL 18.3 on x86_64-windows, 18 `update_logs` rows against

database you are pointed at today is not the same as a suite that refuses to
run against the wrong one tomorrow.

### A-0007 — The production image contains no `.env`

**Relies on:** either no `.env` existing in the build context at deploy time,
or Fly's builder excluding it by some mechanism other than `.dockerignore`.

**Falsified when:** `cat /app/.env` in a running container returns content.

**Consequence:** production credentials are readable by anything with container
access, and travel in every image layer pushed to the registry. Rotation does
not help until the image is rebuilt.

**Status:** ASSUMED, EXPECTED TRUE GOING FORWARD, **AND THE HISTORICAL ANSWER
IS LOST**.

*Original status, retained:* ASSUMED, AND EXPECTED FALSE — `.dockerignore` did
not list `.env` while the Dockerfile does `COPY . .`. ORDER-03 A1 required the
check to run **first, before the fix**, so the answer would be known rather
than merely corrected.

**That ordering was not followed.** `.dockerignore` was rewritten on 2026-09-26
(`F-0017`) and now excludes `.env` at line 5, `.env.*` at line 6 and `.envrc` at
line 8. Deploys after that commit should contain no `.env`. Whether the images
deployed *before* it contained one was never checked, and cannot be recovered
from the current image.

**What this costs.** If `.env` was in those images it is in every layer pushed
to the registry for the life of the project so far, and rotating the
credentials is the only remedy — a question that is now open rather than
answered. `FRED_API_KEY`, `ANTHROPIC_API_KEY`, `AUTH_PASSWORD`, `AUTH_USERNAME`
and `DATABASE_URL` are the secrets in scope.

**Still worth running, two ways.** `ls -la /app/.env` in a current container
confirms the forward-looking half. A prior Fly release, if one is still
retained, would answer the historical half — that is the only route left to it.

### A-0008 — The persisted composite score equals a fresh recompute

**Relies on:** the scorer being a pure function of stored inputs, with no
dependence on wall-clock time beyond the dates in the data.

**Falsified when:** the persisted result and a recompute against unchanged
inputs differ for any country.

**Consequence:** the dashboard serves a stale score with a plausible timestamp
— Principle 11's failure mode, and the same two-producer shape as `A-0001`.
Direction: unknown, which is why it needs a test rather than an argument.

**Status:** ASSUMED. Becomes load-bearing the moment `D-0030` ships; test
specified in `testplan.md`.

### A-0009 — Nothing external consumes `/api/health` beyond liveness

**Relies on:** the Docker `HEALTHCHECK`, Fly's probes and nothing else reading
that endpoint.

**Falsified when:** a monitor, script or dashboard is found parsing its
`last_fred_update` / `last_treasury_update` fields.

**Consequence:** trimming `/api/health` to liveness only, per `D-0033`, breaks
a silent consumer.

**Status:** **VERIFIED 2026-09-26, HOLDS.** See `F-0034`.

`grep -noE "health\??\.[a-z_]+" ui/src/App.jsx` returns a single hit,
`health.status` at line 1758. The two other mentions, at lines 2496-2497, are
ADMIN checklist *strings* telling a human to go and read the endpoint, not code
reading its fields. `fly.toml` and the Dockerfile `HEALTHCHECK` test the status
code only. All four consumers enumerated; none read the pipeline detail.

Because it held, trimming `/api/health` to liveness only broke nothing, which
is what made `D-0035` cheap. Recorded because the fields *looked* load-bearing
and were not — the assumption was worth checking rather than asserting in
either direction.

### A-0010 — `create_all()` has never silently skipped a needed column change

**Relies on:** every schema change since inception having been additive at the
table level, or having been applied by hand.

**Falsified when:** a column's live type or length differs from `models.py`.

**Consequence:** the ORM and the database disagree, and the failure appears as
a write error far from the change that caused it —
`StringDataRightTruncation` being the example already encountered.

**Status:** ASSUMED, AND `error_message` IS ALREADY A KNOWN CASE. A one-query
audit comparing `information_schema.columns` against the models settles it for
every column at once.
